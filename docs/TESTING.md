# V1.0 测试记录

测试日期：2026-10-17。环境：Windows、Node.js 22.14.0、Paseo Desktop 0.12.0-beta.1、本机 Edge 浏览器。所有文档均为可重复生成的合成文件，没有使用个人办公文件。

## 自动测试

运行 `npm run check`，依次构建、检查 TypeScript、生成文件、执行服务器和浏览器测试。

服务器集成测试为 11 项：身份认证、跨来源请求、只读方法、中文目录、四种文件的原始字节和 MIME、文件变化、路径越界、真实 Windows junction 越界、错误反馈、100 MiB 限制和工作区隔离。

浏览器测试为 11 项：四种格式显示、PDF 中文文字和翻页、Word 图片与表格、Excel 数值与公式缓存、PPT 非空画面与翻页、大表导航、空工作表、损坏文件、文件切换与刷新、目录和会话、窄屏布局。测试同时检查未捕获 JavaScript 错误和外部网络请求。

关键核对值：Excel 的负数 `-34.75`、百分比 `12.5%`、日期 `2026-10-17`、公式 `SUM(B3:B4)` 和已保存结果 `1,165.75`。Word 图片须实际加载，不能只检查 `<img>` 节点存在。PDF 和 PPT 的页面不能只检查有 canvas，必须有非空内容。

## Paseo 实际服务

`npm run test:paseo` 连接本机 Paseo，确认 `office-viewer` 状态为 `running`，调用实际 `preview.open` RPC，再通过插件服务读取四种文件并在新的 Edge 实例中显示。该测试需要先在 Paseo 打开此项目工作区。它只读取本项目的测试文件，不创建或启动代理。

桌面操作工具没有成功取得 Paseo 窗口访问授权。因此，Paseo 菜单点击和嵌入式浏览器窗口的人工操作仍需使用者按 README 步骤验收。实际服务测试不替代这项界面检查。

## 安装与命令

在隔离目录测试了仅含仓库文件的首次安装。`scripts/prepare.mjs` 使用锁文件安装生产依赖，再构建所有本地资源。另从项目之外的目录验证了 `paseo` 和 `paseo-office-viewer --help` 的 PATH 解析，并实际启动、停止独立预览服务。

生产依赖的 `npm audit --omit=dev` 在本次检查中报告 0 项已知漏洞。完整开发依赖树仍报告 22 项，包括 Paseo 类型工具依赖的 React Native 工具链和合成 PPT 生成工具的间接依赖。它们不进入预览网页和插件生产安装；没有为了消除报告而强制升级 Paseo 的配套版本。审计结果不等于对所有文档安全性的保证。

## 已修复的实际问题

- 首次安装误把上层项目的依赖当成插件自身依赖，现改为检查当前插件目录。
- Windows 启动命令把磁盘路径用作 ESM import URL，现通过 tsx 的 CLI 入口启动。
- PPT 预览库覆盖原生 `FileReader`，导致 Word 图片读取失败，现恢复原生接口并加入图片加载断言。
- SheetJS 会把某些改名为 XLSX 的文本解释成表格，现先核对 Office ZIP 文件头并显示错误。

## 验证边界

本次检查覆盖合成样例和明确故障。尚未覆盖全部真实 Office 文件、复杂图表、完整字体样式、密码文件、远程主机或手机内嵌预览。Excel 公式不重算。Word 和 PPT 的复杂版式仍应以 Microsoft Office 为准。
